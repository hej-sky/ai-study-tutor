> 生成日期：2026-11-09　|　权威源：<https://gitee.com/hejsky/ai-study-tutor>（tag `v1.5.0`）
> 本目录 `release/` 随仓库一起发布，只放发布物料，**不是 Skill 运行目录**；AI 运行时产物仍按需创建在 `animations/` 与 `images/`。构建中间产物 `release/package/` 不进版本库。

## 0. 一条原则：单一权威源

内容只改 Gitee 仓库；仓库外不再保留第二份发布工作区。`release/` 下所有物料都 **从仓库文档派生**，不要手改 ZIP 里的文件（`release/package/` 已被 `.gitignore` 忽略，可放心在仓库内重跑）。
构建入口按产物分两个，且都不另存内容副本：

- `build_release.py`：技能入口包 `ai-study-tutor-v1.5.0.zip`，从仓库文档派生。
- `build_expert.py`：专家入口包，直接读取上面那个 ZIP 与 `avatar-512.png` 组装，**技能部分逐字节同源**，不复制提示词、不做内容补丁。

原因：每个平台更新都要重新上传、重新审核，且 WorkBuddy 有提交次数限制；手改两份必然分叉。
升版本时先改 `build_release.py` 的 `VERSION = "1.5.0"` 重跑，再把 `build_expert.py` 的 `VERSION` 同步改掉重跑（版本不一致时后者找不到对应技能包会直接报错）；frontmatter、使用说明、ZIP 文件名里的版本号会一起更新（自检会校验一致性）。

## 4-B. 渠道 ②-B 开放平台「专家」入口（Agent 型专家包）

**先读这一段再决定要不要发**：「专家」与「技能」是两类不同资产，解析器不同，同一个 ZIP 不能混用。把技能入口包传进专家入口，会得到「解析失败：未找到 .codebuddy-plugin/plugin.json」——这是**入口选错**，不是文件缺失，不要给技能包补一个 `plugin.json` 硬凑。

| 项 | 技能入口（渠道 ②） | 专家入口（本节） |
|---|---|---|
| 解析器要找的文件 | 压缩包根层 `SKILL.md` | `.codebuddy-plugin/plugin.json` |
| 包结构 | 根目录 / 二级目录 / 文件，最多两级 | 顶层目录 + `agents/` `avatars/` `skills/` `README.md` |
| 本质 | 一份 Skill 定义 | Agent 角色包（人设 + 挂载 Skill 作为能力） |
| 市场位置 | 「专家·技能·连接器 → 技能」 | 「专家·技能·连接器 → 专家」 |

### 上传步骤

1. 在「发布管理 → **专家** → 创建」上传 `ai-study-tutor-expert-v1.5.0.zip`（**只传这一个 ZIP，不要传 `release/` 目录**）。
2. 若仍提示「未找到 .codebuddy-plugin/plugin.json」，改传 `ai-study-tutor-expert-v1.5.0-flat.zip`。两个包内容完全一致，差别只在是否套一层顶层目录：主包对标平台官方 `design-experts.zip` 模板（带顶层目录），备用包按「解析文件须在压缩包根层」的通用经验拍平。平台规则变动快，以当前后台提示为准。
3. 解析通过后确认展示信息：分类选「教育学习」，头像用 `avatar-512.png`，定价保持免费，提交审核后仍需手动点「发布」。

### 包内口径（`build_expert.py` 内定义，不在别处另写一份）

- `expertType: "agent"`（单角色，非专家团）；`categoryId: "15-Education"`。
- `displayDescription.zh` 由脚本校验在平台要求的 40-50 字区间内；`tags` / `quickPrompts` 各固定 3 条，`defaultInitPrompt` 与第一条 `quickPrompts` 相同；三条提示词沿用技能包 frontmatter 的 `examples`，不另造用例。
- Agent 定义文件不复制完整提示词，只声明「加载随包 Skill `ai-study-tutor` 并读取其 `system-prompt.md` 作为唯一权威规则」，避免两份提示词分叉。
- `author.email` 取自本仓库 git 提交作者邮箱，会随包公开；不愿公开只需改 `build_expert.py` 里 `PLUGIN_JSON` 的这一处。
- 头像复用 `avatar-512.png`（512×512 / 12.4 KB / 无文字）。它是扁平图标而非人物插画，符合格式与尺寸硬要求、与技能入口保持同一视觉；若人工审核要求人物插画，再单独生成替换。

### 本地校验

```bash
python release/build_expert.py            # 主包 + 内置预检 + 可复现校验
python release/build_expert.py --flat    # 备用包
```

预检覆盖平台官方字段规范（双语、40-50 字、tags/quickPrompts 数量、路径可解析、无 `tools` 声明、头像规格）与打包卫生（无 `__MACOSX` / `.DS_Store` / 本机路径 / 凭据 / TODO 残留）。另可用 WorkBuddy 官方 `validate_expert.py` 交叉校验：**该脚本内置分类表只有 12 类，不含平台的 `15-Education`，运行时需按平台文档扩展白名单**，否则会误报分类非法。

能力边界口径仍以仓库 `usage-guide.md` 末尾「附：客观能力边界」为唯一权威清单，本节不另写一套。

## 5. 渠道 ③ SkillHub / 通用 SKILL.md 生态

`SKILL.md` 是开放格式，WorkBuddy、ima、QClaw、Claude Code、Codex CLI、Cursor 等都能读同一套目录。所以扩面不需要重写内容，但要**改元数据字段**。

### 5.1 字段差异（上别的市场前先换 frontmatter）

| 含义 | WorkBuddy 开放平台（本包当前） | 腾讯 SkillHub (`skillhub.cn`) | 通用 / 腾讯云 ADP |
|---|---|---|---|
| 标识 | `name`（英文小写 + 连字符，与目录名一致） | `slug`（全网唯一） | 至少 `name` |
| 展示名 | `display_name` | `displayName` | 由平台解析 |
| 简介 | `description` + `description_zh` | `summary` + `description` | `description` |
| 版本 | `version`（必填） | `version`（必填，更新须递增） | 建议语义化版本 |
| 分类 | `category` | `tags` | — |
| 许可 | `license` | `license` 字段可以，**但不能放 LICENSE 文件** | — |

**做法**：把 `release/build_release.py` 的 `FRONTMATTER` 常量换成目标平台口径，重跑脚本生成新 ZIP；不要解压后手改。若 `slug` 被占用，改成 `ai-study-tutor-zlixue` 之类再试。

### 5.2 两个入口

- **SkillHub 网页 / CLI**：实名认证是硬前置；CLI 走 `skillhub login` → `skillhub publish --dry-run`（本地预检）→ `publish --changelog "..."`。Windows 下加 `PYTHONIOENCODING=utf-8`，否则中文会报 GBK 编码错误。发布后状态是「审核中」，通过三线安全审核后自动上架，通常 3~7 天。
- **腾讯云 ADP 技能广场**：控制台 → 资源中心 → 技能 → 自定义技能 → 创建 → 上传 ZIP（≤10 MB，根目录含 `SKILL.md`），格式 / YAML / 安全扫描约 5 分钟。

### 5.3 GitHub 镜像（面向技术用户）

把 Gitee 仓库镜像一份到 GitHub，README 里加一句现成话术即可：

```text
帮我安装这个 GitHub 上的技能仓库：<owner>/<repo>。先读仓库 README 里的安装说明，按你这个工具对应的方式装好，装完告诉我怎么调用。
```

Gitee 仍是国内家长 / 学生的主渠道和**唯一反馈口**，GitHub 只是让技术用户能一行命令装，别把反馈分散。

## 6. 渠道 ④ 扣子 / 腾讯元器等智能体平台（零安装体验入口）

这些平台不装 Skill，而是把提示词贴成「人设 / 系统提示词」，发布成智能体后分享链接，家长点开就能试，**门槛最低**。

1. 新建智能体 → 人设 / 提示词里贴 `system-prompt.md` **代码块内全文**。
2. 欢迎语与 3 个预置问题直接用上架包 frontmatter 的 `examples` 三条。
3. 调试后发布到商店或生成体验链接；说明里写清「完整版与反馈见 Gitee 仓库」。

**这些能力会打折或失效**（要如实告诉体验者）：写文件与产物归档（动画只能给代码）、SVG/CSS 动画播放（取决于平台是否渲染 HTML）、多轮状态保持（不同平台上下文策略不同）、教材照片读图（需多模态模型）、版本字段的跨轮维持。

**提示词可能超平台字数上限**（当前约 490 行，以仓库文件为准）。要不要做精简版是单独的设计决策——你已明确「不能因为省 token 导致学生读不懂」，所以**不要直接砍**。建议先原样试贴，真超限再按这个优先级裁剪：保留年龄适配、防幻觉与安全、答案后置、版本优先、分支导航；只删仓库说明、归档路径、维护类条款。

## 7. 版本更新流程

1. 改 Gitee 仓库 → 跑 `python check_repo.py` → `commit / push`。
2. **两个分支都要推**：Gitee 默认分支是 `master`，当前工作分支常是 `develop`，只推 develop 首页不会更新。打新 tag 并同步两分支。
3. 改 `release/build_release.py` 的 `VERSION` → 重跑脚本 → 自检 PASS。
4. Gitee Release 换新 ZIP；WorkBuddy 后台点「更新版本」重新上传并**重新审核**（会重置头像，记得重传）。
5. 其余平台按各自规则升版本号重发；所有渠道版本号保持一致。

## 8. 避坑清单

- **ZIP 结构（两个入口不同）**：技能包解压第一层必须是 `SKILL.md`，多套一层文件夹会解析失败、目录最多两层（本包 `examples/` 只有一层）；专家包必须有 `.codebuddy-plugin/plugin.json`，主包带顶层目录、备用包拍平。两个构建脚本各自校验，别拿错 ZIP。
- **入口别混**：技能包传进「专家」入口会报「未找到 .codebuddy-plugin/plugin.json」；专家包传进「技能」入口会报「未找到 SKILL.md」。两种报错都不是文件损坏，换入口 / 换包即可。
- **YAML**：两个空格缩进、冒号后必须有空格、不用 Tab、尽量不加引号；`name` 只用英文小写 + 连字符且与目录名一致。脚本已校验。
- **提交次数**：WorkBuddy 每天技能 / 专家各 5 次、每月合计 20 次，驳回重提也算 → 先在本地跑自检再传，别反复重传试错。
- **名称**：含别家平台名会被驳回；「助力学 AI 学习助教」安全。展示名别带「测试」「最终版」。
- **头像**：512×512、JPG/PNG、≤500 KB；「更新版本」会重置头像。
- **过审 ≠ 上线**：必须手动点发布并选「公开发布」。
- **免费 / 付费不可改**：默认免费，别误点。
- **未成年人教育内容**：`description` 不要写「保证提分」等效果承诺；隐私与免责沿用仓库 README 的「内容来源与责任说明」。
- **死链**：派生文档里凡是仓库内指向本地文件的链接都已改成线上地址，脚本会逐处扫描引用（数量随内容变化，不写死）；再改内容后记得重跑自检。
- **能力边界口径**：以仓库 `usage-guide.md` 末尾「附：客观能力边界」为唯一权威清单，本清单只列上架相关风险，不要另写一套说法。

## 9. 反馈收口（实验阶段最重要）

所有渠道只指向一个反馈口：<https://gitee.com/hejsky/ai-study-tutor/issues>。
README 已有话术「不用懂代码、不用懂 git，贴对话截图即可」，最有用的反馈是：孩子哪句话没听懂、哪道题难度不合适、讲解或答案哪里有错、动画能否播放、用的哪一版教材。

WorkBuddy 推广链接按渠道打标签，用来区分「哪个入口带来的人真的在用」；但**反馈不要开第二个口**（评论区、私信、群），收不过来也难以沉淀。跨平台实测按仓库内 `eval-checklist.md` 逐项核对；复测脚本与逐份原始输出保存在维护者本机，不随仓库分发。

## 10. 只能你本人完成的事

1. 各平台实名认证（WorkBuddy 开放平台、SkillHub）。
2. 后台上传 ZIP、填展示信息、提交审核、点「发布」。
3.（可选）Gitee 上创建 Release 并挂附件；不建也能从仓库 `release/` 直接下载 ZIP 与头像。
4. 决定是否开 GitHub 镜像、是否做智能体精简版。
5. 找一个没参与制作的人试装试用，并回填实测结果。

其余（构建、自检、头像、字段适配、版本同步）都可以由 `release/build_release.py`（技能包）与 `release/build_expert.py`（专家包）复跑完成。

## 11. 上架包与仓库的差异对照

| 项 | Gitee 仓库（权威源） | 上架包（派生物） |
|---|---|---|
| `SKILL.md` frontmatter | `name / description / license / agent_created` | 补 `display_name / display_name_en / description_zh / description_en / version / category / author / examples`，`description` 压到 200 字内并写清触发词 |
| `SKILL.md` 正文 | 含「仓库说明」与维护文件加载表 | 加「试试这样问我」3 条示例；删两行维护文件；仓库说明改为线上地址；执行规则未改 |
| `system-prompt.md` | 原样 | **代码块内提示词一字未改**；仅把代码块外「版本历史」的本地链接改成线上地址 |
| `usage-guide.md` | 全文（含安装原理、目录、配套文件、能力边界） | 只留三步上手、常见问题、能力边界、输入区字段；本地死链改线上 |
| `examples/few-shot.md` | 原样 | 只改一处指向规则核对清单的死链 |
| 文件数 / 体积 | 见仓库目录树（根目录文档 + `examples/` + `release/` 发布物料） | 6 文件 / 约 40 KB（ZIP） |
